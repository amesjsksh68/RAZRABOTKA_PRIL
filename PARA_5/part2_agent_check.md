# Часть 2. Спросить агента до себя — Two Sum

**Агент:** Claude Code (модель Claude Opus 5.5)
**Задача:** [Two Sum](https://leetcode.com/problems/two-sum/)

## 1. Что спросил у агента

Дал агенту условие задачи (файл `task`) до того, как решал сам, и попросил решить Two Sum двумя способами («в лоб» и через HashMap), указать сложность каждого и написать вывод-сравнение.

## 2. Что ответил агент

**a. «В лоб»:** по словам агента, время O(n²), память O(1).

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):
                if nums[i] + nums[j] == target:
                    return [i, j]
        return []
```

**b. HashMap (`dict`):** по словам агента, время O(n), память O(n).

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}
        for i, num in enumerate(nums):
            need = target - num
            if need in seen:
                return [seen[need], i]
            seen[num] = i
        return []
```

Вывод агента: «HashMap выигрывает, потому что вместо внутреннего цикла делает один поиск в хеш-таблице за O(1). Итого O(n) против O(n²). На LeetCode оба варианта Accepted, но „в лоб“ работает заметно медленнее».

## 3. Моя проверка

| Что проверял | Как | Результат                              |
|---|---|----------------------------------------|
| Корректность обоих вариантов | тесты из условия (`[2,7,11,15], 9`, `[3,2,4], 6`, `[3,3], 6`) и отрицательные числа | оба проходят ✅                        |
| Сложность «в лоб» O(n²) / O(1) | разбор кода: перебор всех пар (i, j), около n²/2 сравнений | верно ✅                               |
| Сложность HashMap O(n) / O(n) | разбор кода: один проход, словарь до n элементов | верно, но с оговоркой ⚠️ (см. ниже)    |
| Скорость на практике | локальный замер, n = 5000, пара в конце массива | «в лоб» ≈ 523 ms, HashMap ≈ 0.82 ms ✅ |
| Время на LeetCode | отправка обоих вариантов | «в лоб»: 2150 ms, HashMap: 1 ms        |

## 4. Где агент «уверенно ошибся»

Код и итоговые оценки O(n²) / O(n) у агента верные. Ошибки нашлись в формулировках, которые агент выдал как факт:

1. **Результаты LeetCode без запуска.** Агент написал в выводе «на LeetCode оба варианта Accepted, но „в лоб“ работает заметно медленнее», хотя доступа к LeetCode у него нет и решения он не отправлял. Время прогона он фактически придумал. Проверять это пришлось самому.
2. **То же в Contains Duplicate.** Сначала агент утверждал, что решение «в лоб» на LeetCode получает Time Limit Exceeded. Тоже без проверки: только после уточнения он переписал это как «скорее всего».
3. **«Поиск в dict за O(1)» — это не всегда так.** O(1) получается только в среднем (амортизированно). В худшем случае, при коллизиях хешей, поиск занимает O(n), а весь алгоритм деградирует до O(n²). Для тестов LeetCode это неважно, но формулировка «за O(1)» без «в среднем» неточная.

## 5. Вывод

Агент быстро даёт правильный код и стандартные оценки сложности, но так же уверенно пишет то, что не проверял: время прогона на LeetCode и вердикт TLE. Поэтому ответ агента нужно сверять самому: запускать тесты, делать замеры и отправлять решение на LeetCode, а оценки сложности уточнять (среднее или худший случай).
